# 小骆日报 Markdown 格式规范

版本：2026-10-22。适用：当前「海外语聊直播行业日报」标准 Markdown 正文。

本文件约定内容结构与网站排版的对应关系，不代表内容已经完成事实核验，也不会创建、修改或自动发布日报。

## 一、文件与标题层级

- 编码使用 UTF-8，扩展名使用 `.md`。
- 建议文件名：`海外语聊直播行业日报_YYYY-MM-DD.md`。
- 第一行只写一个一级标题：`# 10月22日海外语聊直播行业日报`，日期替换为本期日期。
- 头条与栏目使用二级标题 `##`；具体产品、岗位和事件使用三级标题 `###`。
- `#` 后必须有一个空格。标题前后、不同段落之间留一个空行。
- 不用四级标题、HTML、手动空格或图片来模拟文字排版；不要用加粗标题替代标准 `##`、`###` 层级。
- 编辑器里的期次日期、文章标题日期和文件名日期应一致。网站日期条读取已发布记录的日期，不会根据正文里的某个日期自动建立期次。

## 二、固定结构与顺序

```markdown
# 月日海外语聊直播行业日报

## 头条：具体事件标题

事件事实摘要。

**核心观察：** 为什么值得关注，明确区分事实与分析。

## 01 产品雷达

## 02 排名异动

## 03 团队与招聘动向

## 04 语聊直播产品近一周变化

## 05 今日观察

**小骆语聊：** https://xiaoluo-social.pages.dev/
```

- 五个栏目名称与顺序保持上述写法，编号固定为 `01`—`05`。
- 头条最多一条，放在 `01 产品雷达` 之前；没有可靠头条时可以省略，不造事件填充。
- 某栏没有可核实内容时，保留栏目并写明「暂无可核实的新增信息」，不要填入不相干内容。
- 栏目之间可使用独立的 `---`，上下留空行；网站会由自身样式安排栏目间隔，不需要堆叠分隔线。

## 三、各栏目写法

### 头条

标题使用 `## 头条：产品名＋具体变化`，不要只写「更新」「重磅消息」等空泛描述。

正文先写发生了什么、涉及谁、真实时间和适用范围，再单独写 `**核心观察：**`。事实摘要与分析分段；在对应事实后附具体原文链接。

### 01 产品雷达

栏目开头写 `**榜单口径：**`，包括国家或地区、商店、分类、免费/付费/畅销榜和快照日期。

每款产品使用 `### 产品名｜#名次`，正文分为 `产品类型：`、`观察：` 与来源。未核实的名次不写，不把上榜等同于新上线。

### 02 排名异动

先写 `**榜单口径：**` 和 `**对比日期：**`，两天必须采用同一国家、商店、分类及榜种。

`**排名上升**`、`**排名下滑**` 使用加粗普通段落，下面接无序列表；不要写成 `###`，否则会被当成独立资讯条目。

- 推荐条目写法：`- 产品名：#当前名次，上升 N 位`。
- 只有两个日期的同口径名次均已核实时，才写升降方向与位数。
- 数字越小名次越靠前；名次变动不等于下载量、营收或用户量的同等变化。
- 列表之后单独写 `**怎么看：**`，保留判断限制，不为单日异动臆测原因。

### 03 团队与招聘动向

每项使用 `### 公司或产品｜国家/城市｜岗位名称`。写明职责、要求、可确认的发布日期和实际招聘状态，并附具体职位页。

历史仍在招机会必须注明原始日期，不写成当天新增；页面无法读取或状态不明时，如实说明。

### 04 语聊直播产品近一周变化

每项使用 `### 产品名｜具体变化`。单独注明 `更新日期：` 或 `发布日期：`，正文写实际功能、活动、商业化或运营规则变化，并附原文。

区分公告日期、活动期间、规则生效日期与结算周期。没有可核实的重大功能更新时如实说明，不把「修复已知问题」包装成新功能。

### 05 今日观察

直接使用有序列表：`1. **主题：** 观察与启发。`，不再增加三级标题。

观察必须对应当期证据；不要重复全文、臆测因果或把推断写成确定事实。条数按实际内容，不为固定数量硬凑。

## 四、段落、强调与来源

- 正文为普通段落，不整段加粗；需要强调时，只加粗关键标签或短语。
- 关键排名、数字门槛、活动奖励、生效日期和政策变化使用标准三级星号，例如 `***均位列Top10***`、`***上升24位***`、`***10月28日正式生效***`。自有日报正文与编辑器预览显示为蓝色、700 字重、非斜体，字号跟随所在正文段落，不增加背景、边框或下划线。
- 普通 `**产品类型：**` 等标签仍为普通加粗，不会变蓝。不要给整个段落、标题或来源链接套用蓝色重点语法，也不要用虚假超链接模拟颜色。
- Markdown 源稿中不写 HTML、style、CSS 或颜色代码。通用 Markdown 阅读器会将 `***重点***` 显示为加粗加斜体；蓝色仅由自有网站样式提供。保留导出文件里的星号，不将显示样式回写为 HTML。
- `榜单口径：`、`对比日期：`、`产品类型：`、`更新日期：`、`发布日期：` 各自独立成段，网站会以较小字号作为辅助信息展示。不要把事实正文与这些标签挤在同一段。
- 来源用 `[官方公告](具体原文URL)`、`[职位原文](具体职位URL)` 等 Markdown 链接，紧跟对应事实；多来源可以分行列出。
- 发布前补齐真实、可访问的完整链接，不以搜索结果页、平台首页或模板占位符充当证据。
- 示例：`[来源：Spotify 官方公告](https://具体公告完整地址)`。这是语法示例，不能作为实际来源发布。
- 页尾固定写 `**小骆语聊：** https://xiaoluo-social.pages.dev/`。

## 五、网站展示规则

- 标准 Markdown 的前两个栏目为「产品雷达」「排名异动」时，桌面端左右并排；手机和平板为上下单栏。
- `03`—`05` 保持整行顺序阅读；头条独立展示，不计作编号栏目。
- 日报一级文档标题仍应保留在源文件中。网站不再显示大型重复报头，文档标题用于文章记录与无障碍阅读。
- 序号、字号、字体、颜色、下划线、日期条与「全部日报」入口均由网站代码负责，不写进 Markdown。
- 网站保留日期切换、原文链接及阅读顺序；格式正确不等于事实已核验，也不等于自动发布条件已满足。
- 线上已有的部分纯文本日报有兼容显示，但新稿请保留 Markdown 标记，不依赖猜测层级。

## 六、发布前检查

1. 已替换模板中的所有占位符，没有把模板当成完成稿。
2. 期次、标题与文件名日期一致；事件日期、榜单快照日期、招聘原始日期没有混用。
3. 五栏目名称、编号、顺序正确；产品/岗位/事件用三级标题，排名分组只加粗，观察用有序列表。
4. 排名口径一致，方向和位数有证据；无法核实时明确说明，不硬补数量。
5. 每项事实附对应原文链接，事实与分析分开，历史信息没有伪装成新增。
6. 核对网站预览的头条、两栏、列表及手机排版；再按现有授权和核验流程发布。

可复制的完整模板：`docs/examples/daily-report-template.md`。模板中使用占位符，不含可直接发布的事实。
